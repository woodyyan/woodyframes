Behind the frames.

一个取景框，而不是一个功能很多的网站。

浅色摄影集 / 画廊与分类 / 公开精选作品。这是这一版已经确认的范围：只让照片、留白和文字构成页面，不加入博客、商店、评论、账户或后台。

  • 视觉：暖白纸感底色、衬线标题、细线分隔；用取景框的四角作为唯一的品牌图形。没有装饰性渐变、滤镜或自动轮播。
  • 电影感：一张宽幅精选照片作为开场，横竖作品交错排列；打开大图后画面完整保留，可选择暗场观看。
  • 浏览：四类筛选、画廊 / 紧凑联系表、照片链接、键盘和手机滑动。首屏精选仅做封面裁切，画廊与大图均不裁切。
  • 收藏与整理：作品由你在本地目录和照片索引中管理。这里没有假装能保存到云端的上传按钮，也不以浏览器 localStorage 代替真实归档。

这是一份可交互视觉原型，不是已接入云存储的生产网站。照片已内嵌到离线交付版；正式版不会把整个图库内嵌进 HTML。右下角说明按钮和所有示例标记，均不属于正式网站。

网站无状态，照片有一个持久的家。

推荐 Astro + TypeScript + 原生 CSS + 少量浏览器脚本，构建成静态 HTML，未来部署到 Vercel。仅展示摄影不需要数据库、登录、API 服务或常驻服务器；无需使用 Vercel Functions。

“无状态”不是“不能保存照片”。它指网站运行时不依赖会话、可写本地磁盘或数据库。照片存入对象存储，索引持久保存在 Git，两者都独立于页面服务。

为什么不是一开始就上 Next.js？

Next.js 同样可以使用 output: "export" 实现纯静态。如果你希望统一到 React / Next.js 技术栈，可以选它；但这个项目用 Astro 更精简。Next.js 静态导出不能使用默认的运行时图片优化，要用预生成尺寸或自定义图片 loader。

正式版页面与交付顺序

先实现首页与四类画廊、可分享的静态照片详情页、大图观看；再实现本地选片与图片导出脚本、元数据校验；最后连接 Git 与 Vercel、设置域名 / 图片缓存、测试真实网络与手机浏览。此轮只完成设计原型，不执行 Git 操作或部署。

依据：Astro 静态部署 · Next.js 静态导出。核验日期：2026-10-20。

展示图进对象存储，照片信息进源码。

正式版推荐：Vercel + Cloudflare R2 自定义图片域名。
前提是你愿意用 Cloudflare 管理域名，并以全球访问和流量成本可控为重点。如果已有腾讯云资源或更重视中国内地访问，优先评估 COS + 合适区域的 CDN；上线前必须实测 Vercel 页面与图片两条链路。

选择适合什么注意与建议
源码 public/Logo、图标、少量固定封面；小型初版可以直接被静态部署分发，但大量图片会拖大 Git 历史、克隆和构建。原片不要提交。数十张压缩图可以起步，长期图库不推荐。
Cloudflare R2长期公开图库；重视出站流量成本对象存储出站流量免收费，但存储、操作及额外图片处理不等于免费。生产用自定义域名与缓存规则，不能依赖限流的 r2.dev。R2 不等于自动图片压缩服务。
腾讯云 COS已有腾讯云账号；区域与 CDN 策略更贴近主要访客可配 CDN / 数据万象，也可本地预生成展示图。分别核算存储、请求、出站 / CDN 和图片处理费用；中国内地 CDN 自定义域名需满足备案要求。
Vercel Blob最少平台切换；管理集中在 Vercel公开图可用 URL 直接展示，且有 CDN。留意存储、操作、上传及分发费用。私有 Blob 读取需要鉴权与 Function，不属于本方案的纯静态直读路径。

两类照片，两个隔离的空间

  • 公开展示桶：只有压缩后的展示图；禁止匿名写入；如用 COS，可设私有源站 + CDN 回源授权，对外只公开展示图 CDN。这里的照片本来就是公开的，不承诺防下载。
  • 原片与未公开作品：独立私有桶 + 本地硬盘 / NAS 备份，不进入公开照片索引。对象存储不是唯一备份，保留至少两份独立副本。
  • 访问控制：公开展示意味着任何获得图片 URL 的人都能读取。隐藏链接、前端密码、Referer 防盗链都不构成真正的原片隐私保护。仅把照片放在私有源站，也不自动使 CDN 访问私有。

体量示例，而不是报价

假设 1,000 张，每张原片 25 MB，则约 25 GB；每张三个展示尺寸合计 1 MB，则展示图库约 1 GB。每月 10,000 次访问、每次实际加载 20 张 × 0.25 MB，约 50 GB 客户端图片流量。实际账单还取决于缓存命中、分发路径与处理服务。

官方依据：R2 费用 · R2 公开桶与域名 · COS 域名 / CDN · COS 回源鉴权 · Vercel Blob。价格与额度以开通时官方页面为准。

像整理摄影集一样更新网站。

  1. 本地选片：在 Lightroom / Capture One 或原有目录中维护原片，只选择准备公开的作品。
  2. 导出展示图：统一到 sRGB，生成长边 640 / 1280 / 2560 px 的 WebP（或 JPEG 回退），不放大低分辨率原图，不强行裁切；去掉 GPS 和不必要的 EXIF。
  3. 上传到对象存储：本地脚本仅上传这一批新增展示图。写密钥保存在本地环境变量 / 密钥管理中，采用最小权限，不进入源码、浏览器或公开环境变量。
  4. 生成照片索引：保存唯一 ID、标题、分类、标签、拍摄日期（可空）、地点（可空）、原始宽高、排序、公开状态，以及每个尺寸的 objectKey。所有事实由你提供或从真实文件读取，不猜拍摄信息。
  5. 校验与发布：先确保图片存在、尺寸正确、索引合法；经你批准提交源码后，由 Vercel 构建发布。仅上传图片不会自动出现在画廊，新增条目需要索引更新与一次重新部署。

私有原片空间：与公开展示桶完全分离

保持可迁移：索引存相对 objectKey，通过图片域名配置拼成 URL。不要把厂商签名链接写死在照片数据里；用内容哈希生成新文件路径，配置长期缓存，避免替换图片后一直看到旧版本。

性能与边界

首屏仅预加载精选图，其他缩略图按需懒加载；使用 srcset / sizes，大图只在打开时加载；为图片声明宽高避免布局跳动。图库增长后静态分页，不一次加载所有作品。分享使用真实照片详情页与 Open Graph，不依赖只有浏览器能理解的 hash。

第一期不做网页内上传与排序保存。若以后需要“打开网站就能上传 / 管理”，应另建受鉴权的管理端或接入静态 CMS；展示站仍可静态，但管理能力需要额外授权与持久写入通道。
